## Projection Strategy Evaluation

### Option A — Evolved Generic ProposalSummary (SELECTED)

Add nullable type-specific fields to existing record.

**Pros:** Minimal change, backward compatible, type-safe, proportional to V1.
**Cons:** Record grows from 9 to 19 fields.

### Option B — Typed Proposal Details (REJECTED for V1)

Nested polymorphic detail objects.

**Rejected because:** Greater change surface, requires frontend type discrimination, over-engineered for V1.

### Option C — Raw JSONB Exposure (REJECTED)

Expose payload directly.

**Rejected because:** Violates architectural boundary, couples frontend to AI-engine schemas, no type safety.
