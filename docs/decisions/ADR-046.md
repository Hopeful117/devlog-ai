# ADR-046 — Separate Rich Repository Context from Agent Transport Projection

- **Status:** Accepted
- **Date:** 2026-08-09

## Context

The Repository Context Engine intentionally retains complete scoring, diagnostics, selection
decisions, provenance, content and symbol outcomes. This representation supports immutable AI-task
snapshots, auditing and troubleshooting.

The Engineering Story endpoint previously serialized that domain object directly. A representative
request reported 3,186 selected-evidence tokens but returned 164,445 JSON bytes. Repeated score and
ranking metadata occupied 70,455 bytes and 124 individual selection decisions another 26,094 bytes.
The agent therefore received substantially more transport metadata than actionable context.

The internal context and its existing budget remain correct for their responsibility. An external
engineering agent needs a smaller contract without losing traceability or changing evidence
selection.

## Decision

DevLog separates the two representations:

* `RepositoryContext` remains the authoritative rich Core model;
* the Engineering Story endpoint returns a versioned Agent-Ready projection by default;
* `detail=full` explicitly returns the unchanged rich representation for diagnostics;
* the compact contract preserves `repositoryContext.evidence[].reference` and `.summary` for the
  existing adapter;
* only already selected evidence is projected;
* rejected candidates become sorted aggregate counts by reason;
* projected evidence retains final score, bounded unique reasons, essential provenance, resolved
  revision, bounded content and Java declarations;
* a separate 32 KiB / 8,192 estimated-token policy bounds canonical semantic JSON;
* deterministic degradation removes related references, extra reasons, declarations, content text
  and finally existing tail evidence in that order;
* degradation reports warnings and counters, never re-ranks evidence and never promotes rejected
  evidence;
* the authoritative Repository Context digest is retained and a separate SHA-256 projection digest
  identifies the canonical semantic transport payload;
* generated time, digest and accounting fields are excluded from canonical byte accounting to avoid
  self-reference;
* synchronized repository evidence remains navigation context and direct current-repository
  verification remains mandatory.

Projection is owned by the Java Core `projectcontext` integration boundary and occurs after the
Repository Context engine has completed. Internal AnalysisContext, AI-task snapshots, prompts,
ranking, selection and enrichment are unchanged.

## Consequences

### Advantages

* Agent context windows contain less duplicated diagnostic metadata.
* Transport cost is measured independently from the domain evidence budget.
* Existing agent adapters retain their minimum usable-evidence contract.
* Full explainability remains available without becoming the default payload.
* Domain evolution no longer automatically expands the external agent JSON.

### Trade-offs

* The endpoint now has compact and full response modes that must be documented and tested.
* Repository Context and projection digests intentionally identify different semantic boundaries.
* A very constrained payload may lose tail evidence after optional detail is exhausted.
* Provider-neutral token accounting remains an estimate; UTF-8 bytes are the hard limit.

## Alternatives Considered

### Compress the existing response

Rejected because decompression restores the same verbose JSON inside the agent context window.

### Jackson views or property filters

Rejected because they couple the domain model to one HTTP consumer and do not express a versioned
budget, aggregate decisions, deterministic degradation or a distinct digest cleanly.

### Custom Repository Context serializer

Rejected because context-dependent serialization could change internal AI-task snapshots and hide
the external contract inside infrastructure code.

### Add a model-specific tokenizer

Rejected because exact tokenization depends on provider/model vocabulary. A byte bound and stable
estimate preserve provider independence.

### Change evidence ranking or selection

Rejected because transport compaction must not become a second relevance engine. Selection
precision remains a separate concern.
