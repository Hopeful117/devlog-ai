# ADR-071 - Authorized Read Capability for Story Context Snapshots

## Status

ACCEPTED - approved by the human project owner on 2026-10-01.

## Context

Story 0154 persists an immutable snapshot for a bounded Story Context Agent
execution. The snapshot is execution-scoped, non-trusted and retained for a
limited TTL. The read capability currently needs an explicit authorization
contract independent from snapshot identity and callback authentication.

## Decision

The project exposes one Core-owned, read-only application capability:

```text
readStoryContextSnapshot(
    AuthenticatedPrincipal principal,
    UUID snapshotId
)
```

REST and MCP are thin adapters over that capability. The caller does not
provide the project scope. Core resolves the project from the `AiTask` bound to
the snapshot and evaluates authorization before materializing or mapping the
detailed snapshot.

The mandatory evaluation order is:

```text
authenticate principal
  -> resolve minimal AiTask identity
  -> verify Story Context Agent snapshot
  -> resolve owning project
  -> verify project membership and role
  -> verify snapshot TTL
  -> materialize detailed response
```

The capability will enforce, at minimum:

- principal is authenticated according to ADR-070;
- principal is authorized for the project bound to the `AiTask`;
- `PROJECT_READER` and `PROJECT_OWNER` are authorized to read the snapshot;
- the requested snapshot is an immutable Story Context Agent snapshot;
- the snapshot has not expired according to the existing 30-day TTL policy;
- expired snapshots are never rewritten or resurrected;
- response data cannot expose another project's scope or context;
- MCP and REST return equivalent domain outcomes for equivalent requests.

Public outcomes are deliberately non-disclosing:

- missing authentication maps to `401`;
- unknown, inaccessible, cross-project and expired snapshots map to `404`;
- an authorized non-expired snapshot maps to `200`;
- MCP maps these same domain outcomes to its protocol error representation
  without changing authorization semantics.

The implementation must not leak snapshot existence through an unauthorized
lookup.

## Invariants

1. `snapshotId == aiTaskId` remains an identity invariant, not an authorization
   grant.
2. Authorization happens before detailed snapshot projection.
3. The authorized project scope is read from Core-owned task state, never from
   caller-provided projection data.
4. The capability is read-only and cannot mutate task state, context, grounding
   or trusted knowledge.
5. TTL enforcement and authorization are both fail-closed.
6. REST and MCP cannot implement different authorization rules.

## Out Of Scope

- Creating or migrating the identity provider.
- Changing snapshot retention or snapshot schema.
- Callback authentication changes.
- Authorization for unrelated project, repository or knowledge endpoints.
- Human UI implementation.

## Acceptance Evidence Expected From The Follow-Up Story

- authenticated authorized read succeeds;
- unauthenticated read is rejected;
- principal from another project is rejected;
- unknown and unauthorized identities follow the approved disclosure policy;
- expired snapshots are rejected without mutation;
- REST/MCP behavior is equivalent;
- no snapshot body, prompt, token or secret is emitted in authorization logs.
