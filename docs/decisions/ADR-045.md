# ADR-045 — Bounded Selected Java Symbol Enrichment

- **Status:** Accepted
- **Date:** 2026-08-09

## Context

ADR-044 adds bounded text to selected source and test evidence. The Story 0015 benchmark showed that
useful files receive content, but every returned excerpt can still be truncated. Increasing global
limits would add raw text without reliably exposing declaration structure.

Kiko needs classes, interfaces, records, enums, annotation declarations, constructors, methods, and
annotations primarily for navigation and targeted verification. These are deterministic syntax
facts, not validated knowledge or implementation behavior.

## Decision

DevLog adds a versioned Java-only symbol phase after global evidence selection and before bounded
text enrichment. It:

* considers only selected Java `SOURCE_FILE` and `TEST_FILE` evidence;
* uses JavaParser Core configured for Java 21 without symbol solving or compilation;
* reads complete files only through the existing revision-pinned and confined repository boundary;
* applies independent file, input, symbol, string, token, and duration limits;
* forms a deterministic considered set by allocation rank, file limit, symbol budget, and remaining
  global context budget before parsing;
* exposes structured declaration facts, source locations, policy/extractor identity, revision,
  allocation reasons, truncation, and explicit outcomes;
* fails closed for malformed source and isolates individual failures;
* consumes at most a bounded share of the existing Repository Context token budget before content
  enrichment uses the remainder;
* does not change global candidate ranking or selection.

The symbol phase reports syntax directly present in one file. It does not resolve dependencies,
link symbols across files, infer source/test relationships, inspect bodies, or claim runtime
behavior. The current repository remains the implementation source of truth.

## Consequences

### Advantages

* Selected evidence carries denser navigation context than paths or arbitrary text prefixes alone.
* Java declarations remain deterministic, bounded, revision-traceable, and digest-visible.
* Malformed, unavailable, skipped, and failed extraction remain explicit without removing paths.
* Every considered file has an explicit outcome; selected Java evidence outside the bounded
  considered set remains unchanged and a warning explains the limit.
* Existing request endpoints and global budgets remain compatible.

### Trade-offs

* JavaParser Core becomes a backend runtime dependency.
* Symbol and content phases can synchronize/read the same selected revision independently.
* Syntax-only results cannot replace direct repository verification.
* Java is the only supported language in this increment.

## Alternatives Considered

### Increase content limits

Rejected because more raw text does not guarantee declaration density and increases context cost.

### Use regular expressions or a handwritten partial parser

Rejected because modern Java syntax, nesting, annotations, records, generics, and malformed sources
would make the result fragile.

### Use the JDK compiler tree API

Rejected for this increment because the deployed backend uses a JRE runtime image and DevLog must
not compile target repositories or execute their processors/plugins.

### Add symbol solving

Deferred because dependency and cross-file resolution are outside the deterministic declaration
contract.
