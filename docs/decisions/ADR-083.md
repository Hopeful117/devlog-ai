# ADR-083 - Core-Owned Human Approval of Bounded Live Evaluation Plans

## Status

IMPLEMENTATION AUTHORIZED - final architectural acceptance remains a human gate.

## Context

ADR-082 deliberately separated preparation from campaign authorization. The
prepared plan is now sufficient to identify exactly what would be executed, but
the remaining approval artifact is still produced manually. Manual production
creates drift risk and prevents an authenticated human from approving the exact
Core-owned plan through MCP.

## Decision

Core exposes a second, separate capability that creates an idempotent pending
authorization request bound to one `planId` and `planDigest`, allows only an
authenticated human principal with project authorization to approve that exact
request, and emits a bounded redacted authorization artifact for the existing
runner.

The capability never executes a provider call, reads provider credentials,
changes the plan, changes operational limits, or approves an `AI_AGENT`
principal. The artifact expires no later than the preparation plan.

An approved artifact is single-use. Core exposes an atomic consumption boundary
for the execution principal; the transition is `APPROVED` to `CONSUMED` only
after the plan and digest are revalidated. Consumption is idempotent for the
same execution key, but a different key cannot reuse the authorization. An
ambiguous consumption result fails closed and requires fresh human approval.

## Contract

The artifact contains the existing campaign authorization fields plus
`artifactVersion`, `issuedBy=CORE`, `authorizationId`, `planId`, and
`planDigest`. MCP remains a thin adapter and the Python runner validates these
binding fields before any provider call.

## Constraints Preserved

- OAuth credentials remain inside the AI Engine provider boundary.
- The non-metered pricing contract and operational limits remain mandatory.
- No trusted knowledge or repository state is mutated.
- Existing LIVE runner checks remain fail-closed.
