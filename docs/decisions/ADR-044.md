# ADR-044 — Bounded Selected File Content Enrichment

* **Status:** Accepted
* **Date:** 2026-08-08

## Context

The Repository Context Engine can rank and select multi-module source, test and configuration paths
for an Engineering Story. Paths help navigation but do not expose basic implementation structure.
Reading every candidate before ranking would increase repository I/O, context size and exposure
before relevance is known.

Source content is deterministic repository evidence, not validated project knowledge. It must stay
bounded, revision-traceable and subordinate to the current repository as the implementation source
of truth.

## Decision

DevLog enriches only selected `SOURCE_FILE` and `TEST_FILE` evidence through a versioned
post-selection phase. Path summaries remain the input to deterministic ranking and diverse
selection. After selection, the enrichment phase:

* resolves the repository source from evidence provenance;
* synchronizes the exact commit recorded by repository-structure collection;
* reads normalized repository-relative paths through a confined targeted reader;
* rejects traversal, symlinks, excluded paths, non-regular files, oversized files, binary content
  and unsupported encoding;
* applies limits for enriched file count, characters per file, aggregate characters and remaining
  Repository Context tokens;
* preserves path evidence when content is skipped or unavailable;
* returns explicit complete, truncated, skipped or unavailable content state;
* reconciles final token estimates, decisions, warnings and context digest.

Configuration and all non-source/test evidence remain content-free. Content is returned as an
additive optional evidence field. Existing Engineering Story Context request operations remain
unchanged.

## Consequences

### Advantages

* Kiko receives bounded implementation text for already relevant files.
* Repository-scale content ingestion and content-based circular ranking are avoided.
* Content stays tied to a deterministic Git revision and evidence reference.
* Individual read failures do not remove useful path evidence or fail the complete context.

### Trade-offs

* The source may be synchronized a second time, pinned to the recorded commit.
* Lexical path ranking may spend content budget on a file that later proves irrelevant.
* Bounded excerpts do not provide symbols, call relationships or complete behavior.
* This local bounded mechanism is not a secret-redaction system.

## Alternatives Considered

### Read all candidate content before ranking

Rejected because it expands I/O and exposure before relevance is established and risks circular
content selection.

### Put code into the existing summary

Rejected because summaries normalize whitespace, have a different size role and cannot express
complete, truncated, skipped or unavailable extraction state.

### Add AI summaries or symbol extraction

Deferred. This decision introduces deterministic bounded text only.
